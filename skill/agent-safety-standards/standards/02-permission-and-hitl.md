# 02 越权防护与人在环确认

## 一、权限判定的三个来源（按可信度排序）

| 来源 | 可信 | 用途 |
|---|---|---|
| 会话上下文（登录态、租户、角色） | 可信 | 权限判定的唯一依据 |
| 工具契约（声明所需角色） | 可信 | 校验的前置条件 |
| 模型输出（参数里写的 tenant_id / user_id / role） | **不可信** | 一律忽略 |

硬约束：**身份类参数不接受模型传值**。工具签名里如果出现 `tenant_id` / `user_id` / `role`，必须从会话注入，签名对模型不可见或强制覆盖。

## 二、越权防护清单

- 每个工具在注册时声明所需角色，调用前校验，失败返回 `permission_denied`
- 数据侧必须有租户过滤（行级或库级），不能只在提示词里说"只能查自己的"
- 越权返回不得泄露资源是否存在（统一 `not_found_or_denied`）
- 跨租户批量查询、导出类操作，单独列为高危
- 权限判定逻辑集中在网关 / 拦截层，禁止散落在各工具内部

## 三、高危工具的人在环确认

### 三级分流

| 副作用等级 | 确认要求 |
|---|---|
| 只读 | 无需确认 |
| 写 | 视业务：金额 / 影响面超阈值时确认 |
| 高危 | **必须确认**，无例外 |

### 确认流程（代码实现，不是提示词约定）

```
1. 模型请求调用高危工具
2. 拦截层生成待确认项：工具名、参数摘要、影响面、请求方、过期时间
3. 返回 pending_confirmation 给模型（不是执行结果）
4. 用户显式确认 / 拒绝（走独立 UI 或消息动作）
5. 确认通过 → 执行（带幂等键）；拒绝 / 超时 → 返回明确结果给模型
```

五条硬要求：

1. **模型不能自我确认**：确认动作必须来自人，来源可校验（签名、会话、二次认证）
2. **确认项绑定参数摘要**：确认后参数被改动必须重新确认（防 TOCTOU）
3. **确认项有有效期**：建议 5~10 分钟，过期作废
4. **拒绝与超时都要返回**：`rejected`（用户拒绝）/ `confirmation_timeout`，模型据此调整话术，而不是卡死
5. **确认开关默认开**：配置项 `require_approval: true`，关闭必须写明理由并进审计

### 不可用"文本确认"替代

模型问一句"是否继续？"用户答"是"——**不算**。这句话在对话里，模型可以自己生成也可以在注入下被诱导。确认必须是结构化动作（按钮 / 独立接口 / 二次凭证）。

## 四、执行边界（白名单）

- 可执行的动作以白名单形式注册，模型只能调用已注册工具
- 禁止把模型输出当作可执行代码：SQL、shell、URL 重定向地址、模板表达式都要经过解析与白名单校验
- 文件与网络访问限域：路径前缀、域名白名单，禁止跟随重定向到非白名单域
- 单任务预算（步数、token、金额）达上限即中断，走预算耗尽分支（见 agent-core-standards）

## 五、审计留痕（高危必留）

| 字段 | 说明 |
|---|---|
| trace_id / session_id / step_no | 定位到具体一步 |
| tool_name / side_effect | 工具与等级 |
| params_digest | 参数摘要（哈希），不存明文敏感值 |
| decision | executed / rejected / timeout / blocked |
| approver | 人工确认人（含来源） |
| reason | 拦截或拒绝原因码 |

保留期 ≥ 业务审计要求，且**不可被 agent 自身删除**。

## 六、自查

- [ ] 身份从会话取，模型传的 tenant_id / role 被忽略或覆盖
- [ ] 每个工具有角色校验，数据侧有租户过滤
- [ ] 越权返回不泄露资源存在性
- [ ] 高危工具确认在代码层，模型不能自我确认
- [ ] 确认项绑定参数摘要、有有效期、拒绝与超时都有返回
- [ ] 无"文本确认"充当闸门
- [ ] 高危操作审计字段齐全，agent 无法删除
