# 03 敏感信息过滤、输出过滤与人工接管

## 一、双向过滤（缺一侧即为未完成）

| 方向 | 位置 | 做什么 |
|---|---|---|
| 入向 | 用户输入、外部内容进上下文前 | 识别敏感字段、注入特征打标、必要时脱敏后再进模型 |
| 出向 | 模型输出落到用户 / 下游系统前 | 敏感信息拦截、违规内容拦截、格式校验 |

常见错误：只做输出侧。结果敏感信息已经进了日志、记忆、trace，事后无法收回。

## 二、入向过滤要点

- 敏感字段识别：证件号、银行卡、手机号、住址、口令与密钥、健康信息
- 命中后三种处置，按场景选：
  1. **脱敏后继续**（`138****1234`）：仍需模型理解上下文时用
  2. **打标后继续**（标记"含敏感信息"，禁止写入记忆与日志）：需保留原值推理时用
  3. **拦截并告知**：完全不该进模型的（口令、密钥）
- 用户主动粘贴的密钥类内容：**不进日志、不进 trace、不进记忆**，并提示用户轮换

## 三、出向过滤要点

- 输出到用户前：过敏感信息规则（同入向清单）+ 违规内容规则
- 输出到下游系统（写库、发消息、调第三方）前：过 schema 校验 + 白名单 + 敏感字段检查
- 命中拦截时的返回：给用户一句可理解的话（"这部分涉及账户信息，已做处理"），**不给内部规则细节**（防绕过）
- 过滤必须可配可审计：规则版本、命中规则 id 落日志

## 四、日志与 trace 脱敏

| 位置 | 要求 |
|---|---|
| 应用日志 | 敏感字段掩码；禁止打印完整请求体 |
| trace / span | 参数只存摘要（哈希），不存明文 |
| 模型原始输入输出 | 按需留存，但必须脱敏；留存期明确 |
| 记忆 | 命中禁写清单的字段一律不写（见 context-memory 03） |
| 评测样本 | 真实样本脱敏后才能进评测集与仓库 |

判据：**日志被导出后，能否识别到具体个人**。能，就是泄露。

## 五、失败兜底与人工接管

三类必须有人工接管路径：

| 场景 | 兜底行为 |
|---|---|
| 安全拦截（注入 / 越权 / 高危拒绝） | 明确告知已拦截 + 提供人工入口 |
| 连续失败（重试耗尽 / 工具常错） | 停止自动重试，转人工，附已完成部分 |
| 预算耗尽（步数 / 成本） | 输出已完成部分 + 建议下一步，转人工 |

话术三原则：**说清发生了什么、说清现在能做什么、不说内部实现**。禁止"系统错误，请稍后重试"这类无信息兜底，也禁止把拦截原因码直接抛给用户。

## 六、审计与可回溯

- 每个拦截事件：`trace_id / session_id / step_no / 命中规则 / 处置 / 是否人工介入`
- 每次人工接管：接入人、时间、交接内容摘要
- 审计日志**只追加**，agent 侧无删除权限
- 保留期与业务审计要求对齐，到期归档而非物理删除

## 七、自查

- [ ] 入向与出向两侧都有过滤，不是只做一侧
- [ ] 敏感字段处置策略明确（脱敏 / 打标 / 拦截）
- [ ] 用户粘贴的密钥不进日志、trace、记忆
- [ ] 日志与 trace 已脱敏，参数只存摘要
- [ ] 三类兜底（拦截 / 连续失败 / 预算耗尽）都有话术与人工入口
- [ ] 兜底话术不泄露内部规则与实现
- [ ] 拦截与接管事件字段齐全，审计只追加
