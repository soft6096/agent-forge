# 能力清单（1.1）

## 做什么

产出 `1.1-能力清单.md`，三段必填：

1. **正向能力**：每条一句、可观测、可判定
2. **负向边界**：至少三条明确不做的事；无法确认时的标准动作（追问 / 拒答 / 转人工）
3. **成功判据**：每条正向能力对应一句"什么算完成"

## 执行规则

1. 需求原文逐条映射，不允许静默消失；无法归类的单列「待澄清」
2. 禁止把技术实现写进能力清单（"用 RAG" 是实现，"能回答产品手册内的问题" 才是能力）
3. 成功判据禁止出现"体验好""较准确""基本可用"这类不可判定表述
4. 需求含糊时先问，不自行补全

## 输出格式

| 编号 | 正向能力 | 成功判据 | 优先级 | 依赖 |
|---|---|---|---|---|

下方接「负向边界」列表与「待澄清」列表。

## 完成标准

- [ ] 正向能力全部可判定
- [ ] 负向边界至少三条
- [ ] 需求原文每条都有映射或无映射说明
- [ ] 用户已确认（未确认不得进 1.2）
