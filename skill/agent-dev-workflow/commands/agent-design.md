# agent 架构方案（3.1）

## 做什么

每个功能项一份 `3.1-<功能>-agent架构方案.md`，加载 `agent-core-standards`；`agent-context-memory-standards` / `agent-tool-standards` / `agent-rag-standards` 均规划中（第二批），按 `check-agent-standards` 第 11~15 / 5~8 / 16~18 项代替。六段必填：

1. 循环形态（单轮 / 工具循环 / 规划-执行 / 多 agent），含选择与放弃理由
2. 状态机（阶段、流转、每阶段退出条件）
3. 上下文预算表（系统提示词 / 工具描述 / 历史 / 检索片段 / 输出预留，溢出先裁谁）
4. 记忆策略（会话内保留、跨会话沉淀、写入判据、遗忘）
5. 工具清单（引用 3.2，此处只列名称与用途）
6. 降级路径（模型失败 / 工具失败 / 检索无命中 / 超预算）

## 执行规则

- 必须附「验收场景」段，逐条对应 2.1 的样本编号
- 预算表必须是具体 token 数字，不能写"尽量少"
- 改了主链路等于改了期望，必须登记产物同步记录
- 不在本步写代码

## 完成标准

- [ ] 六段齐全，无空段
- [ ] 预算表有具体数字且加总不超窗口
- [ ] 降级路径每条有明确行为
- [ ] 验收场景与 2.1 样本编号可对应
- [ ] 用户已确认（未确认不得进 3.2）
