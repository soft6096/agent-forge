# 规范核对（6.1）

## 做什么

加载 `check-agent-standards`，先跑脚本再人工判定，产出 `6.1-规范核对报告.md`。

## 执行规则

1. **编码的 agent 不自评**：本步由独立步骤执行，写码方只能提供改动范围
2. 脚本优先，用技能目录的绝对路径（脚本不在被检项目里，相对路径必失败）：
   `python3 ~/.agents/skills/check-agent-standards/scripts/check_agent_standards.py --project <根> --changed`
   装到其它工具时把 `~/.agents/skills` 换成该工具的技能目录；无 Python 回退 grep 手工
3. 每项结论必须附「文件:行号」证据，禁止"已符合"无证据
4. 未通过项列待确认清单，与用户确认后补齐，不自行删项
5. 不允许把"不影响功能"作为跳过理由

## 修复后复核（强制）

有未通过项时，修完**必须复核**，不允许口头宣布通过：

1. 用同一条命令、同一范围重跑脚本，把新结果追加到 6.1 报告的「复核记录」段
2. 逐项对照：原 fail 项是否转 pass，是否出现新增 fail
3. 豁免项必须仍满足豁免理由，否则重新判定
4. 报告速览的「结论」只在最后一轮复核通过后才写「可进 7.1」

| 轮次 | 日期 | 扫描命令 | 通过 / 未通过 / 待确认 | 结论 |
|---|---|---|---|---|
| v1 | | | | 需补齐 |
| v2 | | | | 可进 7.1 / 仍需补齐 |

## 报告结构

| 项 | 结论 | 证据 | 处置 |
|---|---|---|---|

末尾给：通过项数 / 未通过项数 / 待用户确认项 / 复核轮次。

## 完成标准

- [ ] 全部核对项有结论
- [ ] 未通过项已处置或已确认豁免（豁免需写明理由）
- [ ] 用户已确认（未确认不得进 7.1）
