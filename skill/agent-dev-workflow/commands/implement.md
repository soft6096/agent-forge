# AI 编码（5.1）

## 输入

- `4.1-任务拆解.md`
- `3.1-*-agent架构方案.md`、`3.2-工具清单与契约.md`
- `2.1-评测口径与数据集.md`（评测集已存在，编码期间不得修改样本以迁就实现）

## 执行规则（硬性）

1. 严格按 Phase 顺序：基础设施 → 公共组件 → 评测集 → 主循环 → 工具 → 记忆检索 → 安全 → 评测
2. 写代码前按 SKILL.md 加载矩阵加载对应规范技能，按单文件精确加载，禁止整目录读入
3. 遵守 0.0 的 11 项基线：超时、步数上限、成本上限、日志字段一个都不能省
4. 提示词外置并带版本，禁止在业务逻辑里硬编码
5. 工具错误返回按 3.2 的错误语义实现，不得临时发明格式
6. 硬编码参数（阈值、上限、模型名）一律提到配置
7. 每个任务完成后跑完成标志验证，过了才算完成
8. 一次专注 1~3 个任务，一批收尾后重读任务描述再开下一批
9. **编码完成即停**，不自行做规范核对、不自行跑评测、不声称已通过

## 输出

- 代码（按任务粒度组织）
- `5.1-编码指令.md`：改动文件清单、对应任务、遗留项

## 完成标准

- [ ] 每个任务完成标志已验证
- [ ] Phase 0.5 公共组件已实现且被复用
- [ ] 无任务外改动、无顺手优化
- [ ] 已停下报告，等待 6.1 规范核对
