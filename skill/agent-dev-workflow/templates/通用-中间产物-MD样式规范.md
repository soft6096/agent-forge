# 中间产物 MD 样式规范

> 使用说明：所有 agent-forge 中间产物统一按本规范排版，保证可扫读、可 diff、可被 agent 稳定解析。
> 违反项：标题层级跳级、速览框缺失、表格列不对齐、用段落罗列本应是表格的内容。

## 一、必备结构

每份产物按以下顺序组织：

1. **一级标题**：`# <产物名> - <对象名>`
2. **使用说明引用块**：以 `> 使用说明：` 开头，写清本步的硬要求与禁止项（不超过 6 行）
3. **速览框**：`> [!IMPORTANT] 文档速览` + 两列表（项目 / 内容），5~8 行
4. **正文各节**：`## 一、二、三…`，节内优先用表格
5. **确认清单**：末尾用 `## 确认` + 复选框列表（`- [ ]`），只列硬性条件

## 二、标题规范

| 层级 | 用法 | 示例 |
|---|---|---|
| H1 | 每份文件仅一个 | `# 能力清单 - 客服助手` |
| H2 | 一级小节，中文序号 | `## 一、正向能力` |
| H3 | 表格前的细分 | `### T1 search_docs` |
| 加粗 | 行内强调关键约束 | **未确认禁止进入 5.1** |

## 三、表格规范

- 表头必须有分隔行，列数与内容行一致
- 短字段不长于 20 字；长文本允许 `<br>` 换行，不允许塞进单元格后无标点连写
- 结论类单元格只用固定词：通过 / 未通过 / 待确认 / 不涉及 / 已豁免
- 禁止空单元格；暂无内容写 `—` 或 `待填`

## 四、状态与标记

| 标记 | 含义 |
|---|---|
| ✅ | 已完成并确认 |
| ⏳ | 进行中 |
| ⏸ | 断点，等待输入 |
| 🔲 | 待办 |
| ⏭ | 跳过（必须写理由） |
| **未确认禁止进入 X** | 硬闸门，不得绕过 |

## 五、证据写法

任何"符合""通过"的结论必须附证据，格式统一：

```
文件路径:行号
```

无证据的结论视为未填写。禁止"已符合规范""检查通过"这类无指向表述。

## 六、数字与口径

- 百分比写 `82%`，不写 `82 %`
- 比 baseline 的变化写 `+3 / -3 个点`，不写"略有提升"
- token、时延、成本必须带单位
- 时间统一 `YYYY-MM-DD`，需要精确时刻时用 `YYYY-MM-DD HH:mm`

## 七、术语一致

| 术语 | 统一写法 | 禁止 |
|---|---|---|
| 智能体 | agent | Agent / 代理人 |
| 工具调用 | 工具调用 | 函数调用（指同一概念时） |
| 上下文 | 上下文 | 会话上下文（混用时） |
| 评测 | 评测 | 测评 / 测试（指 agent 效果评估时） |
| 能力清单 | 能力清单 | 功能清单 |
