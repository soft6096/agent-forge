# 能力清单 - <agent 名>

> 使用说明：第 1.1 步产物。agent 项目失败多为**边界失控**而非功能缺失，所以本清单的重点是「负向边界」。
> 三条硬要求：
> 1. 每条正向能力必须**可判定**（"能回答产品手册内的问题"可判定，"回答得准"不可判定）
> 2. 负向边界至少三条，且写明无法确认时的标准动作（追问 / 拒答 / 转人工）
> 3. 需求原文**逐条原样落盘**并按 R 编号映射，不允许静默消失；无法归类的进「待澄清」
> 4. 跨会话接手只认本文件：需求原文没粘进来，等于需求没有来源，7.1 的覆盖核对无从复核
> 禁止把技术实现写进能力（"用 RAG""接向量库"是实现，不是能力）。
