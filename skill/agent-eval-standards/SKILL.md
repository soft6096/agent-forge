# Agent 评测规范

## 定位

agent 的输出是分布式的、非确定的：同一输入两次结果可能不同，改一句提示词可能修好 A 又弄坏 B。**没有评测就没有开发**，只有"感觉变好了"。本技能定义怎么把"效果"变成可统计、可比较、可门禁的数字。

## 六条硬规则

1. **分层是底线**：冒烟 / 回归 / 黄金 / 对抗四层，缺回归集视为没有评测
2. **样本必须含失败样本**：只收集成功案例的评测集测不出退化
3. **判定优先规则断言**：能用代码判的绝不用模型裁判
4. **用裁判必须校验**：报裁判模型、rubric、与人工标注的一致率，未校验的裁判结论无效
5. **指标至少六项**：通过率、工具正确率、平均步数、平均 token、P95 时延、单任务成本，只有准确率不算评测
6. **门禁分层设**：冒烟集必须全绿，回归集不许降，黄金集允许小幅波动但必须说明

## 三条反模式（出现即打回）

- 让写码的 agent 自己生成评测集、自己跑、自己宣布通过
- 报告只写"通过率 92%"，没有样本数、没有基线、没有失败样本
- 样本量 20 条却报"提升 0.3 个百分点"——统计上没有意义

## 交付前

评测报告必须能回答三个问题：各层通过率是多少、比基线变化多少、失败样本归到哪类原因。答不出即不合格。
