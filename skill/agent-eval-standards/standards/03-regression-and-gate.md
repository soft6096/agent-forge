# 03 回归、门禁、归因

## 一、基线管理

| 要素 | 要求 |
|---|---|
| 基线对象 | 一次具体运行的结果快照（含代码版本、模型版本、提示词版本、评测集版本） |
| 基线内容 | 每层通过率、各指标数值、失败样本 id 列表 |
| 何时可刷新 | 正式版本发布后，且新基线不低于门禁；刷新需人工确认 |
| 不可比的情况 | 评测集变了、模型版本变了、判定方式变了——必须重新建立基线并说明 |

规则：基线不是"上次跑的结果"，是"上次确认可交付的版本结果"。禁止拿一次偶然跑得好的结果当基线。

## 二、三层门禁

| 层 | 条件 | 不满足时 |
|---|---|---|
| 提交门 | 冒烟集 100% | 直接阻断提交 |
| 版本门 | 回归集不下降 + 黄金集 ±3 点内 + 成本与时延不超 20% | 阻断发布，回到定位 |
| 上线门 | 版本门 + 对抗集 100% + 人工验收 | 阻断上线 |

门禁阈值必须写在配置里，不能只写在文档里（否则永远不知道实际执行的是哪一版）。

## 三、失败归因分类

每条失败样本必须归到唯一一类，便于统计与分派：

| 类别 | 判据 | 常见修法 |
|---|---|---|
| 理解错 | 没读懂用户意图 | 改提示词 / 补澄清追问 |
| 工具选错 | 选错工具或漏选 | 改工具描述与粒度 |
| 参数错 | 选对工具但参数不合约束 | 改 schema 与示例 |
| 事实错 | 检索到错内容或编造 | 改检索 / 加强拒答 |
| 流程错 | 步数超限、循环、顺序错 | 改骨架与状态机 |
| 拒答误杀 | 该答却拒答 | 放宽安全规则 |
| 安全漏放 | 该拒却执行 | 加拦截规则 |
| 其他 | 以上都不属于，写清原因 | 单独立项 |

规则：

- 失败归因分布是优化优先级依据：某类占比高，先修那一类
- 归因后必须落到具体修法，不允许只写"已记录"
- 同一失败样本连续 3 个版本未修好，升级为架构问题讨论

## 四、失败样本回流

| 阶段 | 动作 |
|---|---|
| 线上发现 | 记录完整输入、上下文快照、实际输出、期望输出 |
| 脱敏 | 去除个人信息与业务敏感数据 |
| 入集 | 归入回归集，标注 source=feedback |
| 复现 | 本地必须能稳定复现后再修 |
| 验证 | 修复后该样本必须由失败转通过，且不得引起回归集其它样本下降 |

## 五、报告必答三问

1. 各层通过率是多少（带样本数）
2. 与基线相比变化多少（带幅度与统计有效性说明）
3. 失败样本集中在哪类原因（带占比与修法）

任何一问答不出，报告不算完成。

## 六、自查

- [ ] 基线含四个版本号（代码/模型/提示词/评测集）
- [ ] 三层门禁阈值写进配置
- [ ] 失败样本逐条归因到唯一类别
- [ ] 回流样本已完成脱敏与复现验证
- [ ] 报告三问可答
