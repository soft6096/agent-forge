# 01 数据集与样本

## 一、四层结构

| 层 | 规模 | 跑的频率 | 作用 | 门禁 |
|---|---|---|---|---|
| 冒烟集 | 5~15 | 每次改动 | 主路径不被破坏 | 必须 100% |
| 回归集 | 只增不删 | 每次提交 / 每日 | 历史失败不复发 | 不允许下降 |
| 黄金集 | 50~200 | 版本对比 | 版本间可比 | 允许 ±3 点并说明 |
| 对抗集 | 按风险面 | 上线前 | 注入、诱导、越权、边界 | 必须 100% 拦截 |

规则：

1. 回归集只增不删。样本过时只能标记 `deprecated` 并保留，不许物理删除（否则历史退化无从比对）
2. 黄金集的答案必须**人工确认过**，来源要写进样本
3. 对抗集每条必须写清"期望是拒答 / 转人工 / 拒执行"，不能只写"应该拦住"

## 二、样本字段

| 字段 | 必填 | 说明 |
|---|---|---|
| id | 是 | `<层>-<序号>`，例如 `reg-0012`，全局唯一且不复用 |
| input | 是 | 用户原始输入，保留真实表述（不要美化） |
| context | 是 | 会话前状态、可用工具、知识库版本、租户 |
| expected | 是 | 期望输出，或必须满足的断言列表 |
| judge | 是 | 判定方式：exact / rule / llm |
| difficulty | 是 | easy / medium / hard |
| source | 是 | real（线上或用户真实提问）/ synthetic（构造）/ feedback（回流） |
| failure_mode | 否 | 对应失败模式编号，如 F2 串工具 |
| tags | 否 | 场景标签，便于分组统计 |

反例：`expected` 写"回答应该准确、专业"——不可判定，等于没写。

## 三、覆盖度怎么算

按**能力 × 场景**做二维覆盖，不是按条数堆。

| 维度 | 要求 |
|---|---|
| 能力覆盖 | 1.1 能力清单每条正向能力至少 3 条样本（简单/中等/困难各一） |
| 失败模式覆盖 | 1.2 每条失败模式至少 1 条样本 |
| 工具覆盖 | 每个工具至少 2 条样本（正常 + 参数错误） |
| 边界覆盖 | 拒答、超范围、多轮指代、超长输入各至少 1 条 |
| 对抗覆盖 | 注入、越权、诱导各至少 2 条 |

覆盖率低于 80% 时报告必须显式写出未覆盖项。

## 四、样本来源配比

| 来源 | 建议占比 | 说明 |
|---|---|---|
| 真实 | ≥ 50% | 线上日志或用户真实提问，最能暴露问题 |
| 构造 | ≤ 40% | 边界与对抗，真实场景难以自然出现 |
| 回流 | 持续增加 | 每次线上失败必须转成回归样本 |

规则：不允许 100% 由模型生成。模型生成的样本用于扩充，但必须人工抽查确认。

## 五、样本维护

| 场景 | 处理 |
|---|---|
| 需求变更导致期望变化 | 新增样本并标记旧样本 `deprecated`，写明失效原因 |
| 模型升级导致整体迁移 | 重建黄金集，旧集保留用于对比 |
| 样本本身有歧义 | 立即修正并记录，禁止"这次先跳过" |

## 六、自查

- [ ] 四层齐全，回归集非空
- [ ] 每条样本九字段（前七必填）齐全
- [ ] 能力覆盖 ≥ 80%，未覆盖项已列出
- [ ] 真实来源占比达标
- [ ] 无模型 100% 自产的评测集
