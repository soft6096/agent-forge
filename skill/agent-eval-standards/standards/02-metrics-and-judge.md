# 02 指标与判定方式

## 一、指标清单（六项起步）

| 指标 | 定义 | 计算 | 用途 |
|---|---|---|---|
| 任务通过率 | 满足期望的样本占比 | 通过 / 总数 | 主指标 |
| 工具选择正确率 | 选对工具的样本占比 | 正确选择 / 需要工具的样本 | 定位串工具 |
| 参数正确率 | 参数完全正确的调用占比 | 正确调用 / 总调用 | 定位 schema 设计问题 |
| 平均步数 | 完成任务的平均循环步数 | 总步数 / 成功率样本 | 定位冗余与死循环 |
| 平均 token | 单任务 token 均值 | 总 token / 样本数 | 成本代理指标 |
| P95 时延 | 95 分位耗时 | 排序取分位 | 体验 |
| 单任务成本 | 金额或等价 token 成本 | 按价格表换算 | 商业可行性 |

规则：

- 主指标之外，必须至少有一个**成本指标**和一个**时延指标**，否则优化方向必然跑偏
- 工具类指标只在"需要工具"的样本上计算，不能混入纯问答样本稀释
- 分位数用 P50/P95，不用平均值代替时延体验

## 二、判定方式优先级

1. **精确匹配**：输出是枚举、ID、数字、固定格式 → 直接用
2. **规则断言**：可用代码判定的结构或行为 → 优先写断言函数
   - 是否调用了指定工具
   - 参数是否满足约束
   - 是否包含必需字段
   - 是否触发拒答
   - 步数是否超限
3. **模型裁判**：只在语义质量无法规则化时使用，且必须过第三部分的校验

反例：用裁判判断"是否调用了 weather 工具"——这是规则一秒钟能判的事。

## 三、模型裁判的六个坑

| 坑 | 表现 | 对策 |
|---|---|---|
| 位置偏差 | 总是偏好前一个候选 | 随机化顺序，双向各判一次 |
| 长度偏差 | 长答案得分高 | rubric 明确"简洁不扣分"，附长度无关的判据 |
| 自我偏好 | 同族模型给自己输出高分 | 换不同厂商模型，或用人工抽检校准 |
| 无"不确定" | 被迫二选一 | rubric 增设 unsure 档，统计 unsure 率 |
| 评分漂移 | 同一输入两次分数不同 | 固定 temperature=0，固定 rubric 版本 |
| rubric 含糊 | "回答质量好"这类判据 | rubric 每条必须是可判定的具体条件 |

必须记录：裁判模型名与版本、rubric 版本、温度、抽检样本数与一致率。

一致率要求：抽 ≥ 30 条人工标注比对，一致率 < 80% 时裁判结论无效，必须改 rubric 或退回人工。

## 四、统计波动

| 样本量 | 可用结论 |
|---|---|
| < 30 | 只报通过/不通过，不报百分比差异 |
| 30~100 | 报百分比，变化幅度 < 5 点视为无差异 |
| > 100 | 可报小幅差异，需说明置信区间 |

规则：

- 报差异必须带样本数，`92%（n=25）` 优于 `准确率提升 3%`
- 同一版本连跑 3 次，波动范围要记录（run-to-run variance），超过 5 点说明评测不稳定，先修评测

## 五、指标与门禁的关系

| 指标性质 | 门禁方式 |
|---|---|
| 冒烟通过率 | 硬门槛，必须 100% |
| 回归通过率 | 不许低于基线 |
| 黄金集通过率 | 允许 ±3 点，超出需书面说明 |
| 平均 token / 成本 | 不许超基线 20% |
| P95 时延 | 不许超基线 20% |
| 对抗拦截率 | 硬门槛，必须 100% |
