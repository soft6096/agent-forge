# Agent 检索增强规范

## 定位

RAG 的失败几乎都不是"向量库不好用"，而是三件事没定：**切分没按语义、召回没设阈值、命中不知道对不对**。本技能把这三件事变成可判定项。

## 九条硬规则（可核对）

1. **切分按结构不按字数**：优先按标题 / 段落 / 表格行切，字符长度只是上限；相邻块必须有重叠（建议 10%~15%）
2. **每个块必须可回溯**：带文档 id、版本、章节路径、原文偏移，否则引用无法定位
3. **召回必须有上限与阈值**：`top_k`（一般 5~10）+ 相似度阈值同时设，只有 top_k 等于必然注入噪音
4. **无命中必须有分支**：低于阈值时不硬塞低分片段，走拒答 / 告知 / 转人工
5. **引用必须强制**：回答里的事实性内容要能指到块 id；提示词里要求引用，且缺引用时有校验
6. **权限过滤在召回前**：按租户 / 可见范围过滤，不能召回后再靠提示词"不要用这些"
7. **索引更新有策略**：增量优先，删除必须生效（软删的块不得再被召回）
8. **查询改写有边界**：改写只能扩召回，不得引入原文没有的约束；改写前后的召回结果都要能对比
9. **必须有离线召回评测**：固定 query 集 + 期望块，算 Recall@k 与 MRR，改动前后对比

## 三条反例（出现即返工）

- 固定 500 字硬切，把一张表的表头与数据切到两个块里
- `top_k=20` 且无阈值，检索永远返回 20 条，模型被迫在噪音里找答案
- 检索无命中时把空数组直接塞给模型，模型自由发挥编造答案

## 交付前

检索链路写完，过 `check-agent-standards` 的「检索」类核对项（第 16~18 项：召回上限与阈值、强制输出引用、未命中分支），每项附文件行号证据；"切分是否按语义""引用是否真的强制"属语义项，人工判定并附一个真实 query 的召回样本。
