# 01 切分、embedding 与索引

## 一、切分

### 优先级（按顺序尝试）

1. **文档结构**：标题层级 → 段落 → 列表项 → 表格行
2. **语义边界**：句子边界（句号、分号），不切断句子
3. **长度上限**：最后才用字符数兜底

反例：固定 500 字切，把表头与数据切开、把"如下所示"与它引用的列表切开。

### 参数起点

| 文档类型 | 块大小 | 重叠 | 说明 |
|---|---|---|---|
| 结构化文档（手册、SOP） | 按章节，300~700 字 | 10%~15% | 保留层级路径 |
| 表格为主 | 一行一块或一组行 | 表头随块冗余 | 表头必须跟着数据走 |
| FAQ / 条款 | 一问一答 / 一条一款 | 边缘重叠 | 一条一款不切 |
| 长报告 | 按小节 | 10% | 保留上一节标题 |

重叠的用途是防止跨块问题漏召回，**不是越多越好**：重叠过高会让同一内容重复占位，挤占上下文。

### 每块必带元数据

| 字段 | 用途 |
|---|---|
| doc_id / doc_version | 回溯与失效 |
| chunk_id | 引用定位 |
| section_path | 章节路径（如"第三章 > 3.2 退款"） |
| offset | 原文起止位置 |
| tenant_id / visibility | 权限过滤（召回前用） |
| updated_at | 索引更新判断 |
| content_hash | 去重与增量 |

**缺 chunk_id 或 section_path 的块不可用**：引用无从落地，模型只能说"根据文档"。

## 二、embedding

- 选型看**语言与领域**，不是看榜单第一：中文优先中文或多语模型，代码 / 法条另测
- 维度不是越高越好：维度 × 条数直接决定索引内存与检索成本
- **必须固定模型与版本并记录在索引元数据里**；换模型 = 全量重建索引 + 重跑召回评测
- 查询侧与文档侧必须用**同一模型**（同一版本），混用是召回差的常见原因
- 归一化与距离度量（cosine / ip / l2）要成对配置，混用会导致分数不可比

## 三、索引结构与更新

| 项 | 要求 |
|---|---|
| 主键 | chunk_id 唯一，删除用软删标记 + 定期清理 |
| 分区 | 按租户或业务域分区，便于权限过滤与独立重建 |
| 版本 | 索引带版本号，与 embedding 模型版本绑定 |
| 更新方式 | 增量优先（按 content_hash 判断变更） |
| 删除 | 文档删除必须同步删块；软删块**不得再被召回** |
| 重建 | 全量重建前先建新版本索引，切换后再删旧，避免服务中断 |

### 索引任务硬要求

- **幂等**：同一文档重复入库不产生重复块（按 doc_id + chunk_id + content_hash 去重）
- **可重入**：中途失败从断点继续，不要求从头重跑
- **失败可见**：入库失败要记录并在看板暴露，不能静默跳过
- **变更可审计**：新增 / 更新 / 删除块数量按批次记录

## 四、常见坑

| 现象 | 多半是 |
|---|---|
| 召回内容总差半句 | 切分没按句子边界，或重叠不足 |
| 表格类问题总答错 | 表头与数据被切到不同块 |
| 更新文档后仍返回旧内容 | 增量没生效 / 缓存键没带索引版本 |
| 删掉的文档还能被召回 | 软删块未过滤 |
| 换 embedding 后效果变差 | 查询与文档侧模型不一致，或未重建索引 |

## 五、自查

- [ ] 切分按结构优先，重叠 10%~15%，不切断句子
- [ ] 每块有 chunk_id、section_path、offset、tenant_id
- [ ] embedding 模型与版本已记录，查询与文档侧一致
- [ ] 索引有版本，与模型版本绑定；重建走"新建 → 切换 → 删旧"
- [ ] 索引任务幂等、可重入、失败可见、变更可审计
- [ ] 软删块不会被召回
