# 03 引用、拒答、权限与离线评测

## 一、引用必须能落地

### 格式

行内标记 + 文末列表：

```
退款需在签收后 7 天内申请 [1]，超期需人工审批 [2]。

[1] 售后手册 v3 > 3.2 退款时限（chunk: kb-4821）
[2] 售后手册 v3 > 3.4 超期处理（chunk: kb-4827）
```

三条要求：

- 引用指向 **chunk_id + section_path**，不指向"文档"这种粗粒度
- 模型不得编造 chunk_id：渲染前必须校验 id 存在于本次召回结果集合
- 无引用的结论视为不可信：事实性段落缺引用要打回重答或标注"未找到依据"

### 怎么强制（三道）

1. 提示词要求：回答事实性内容必须带 `[n]`，列表必须给出处
2. 生成后校验：解析引用，校验 id 属于召回集合；越界 id → 判为编造，重答或降级
3. 评测校验：引用准确率进评测集（引用对了但内容错、内容对了但引用错，分别统计）

## 二、无命中与拒答

### 三种结果要分开

| 情形 | 行为 | 话术原则 |
|---|---|---|
| 分数低于阈值（无命中） | 拒答或告知未找到 | "知识库里没有查到相关规定" |
| 分数够但内容不覆盖问题 | 部分回答 + 声明缺口 | "找到了 X，但 Y 部分没有依据" |
| 命中但涉权限 | 按无权限处理 | 不透露资源是否存在 |

### 硬约束

- **禁止把低分片段硬塞给模型**：宁可不答，也不要答错
- **禁止用模型常识补知识库的缺口**：领域问答里"通用常识"往往是错的
- 拒答要给**下一步**：换个问法 / 提供人工入口 / 说明可查范围
- 拒答率要监控：突升说明索引或阈值有问题（见 agent-ops-standards）

## 三、权限过滤（召回前，不是召回后）

- 每条块带 `tenant_id` / `visibility`，检索请求带上调用者身份，**在检索层过滤**
- 禁止"先召回再靠提示词说不要用"——内容已经进上下文，等于已泄露
- 跨租户共享的公共知识库要有明确标记，与私有块分开索引或分开过滤字段
- 权限变更要能影响已有索引：可见范围变化后，增量更新对应块的 visibility

## 四、脏数据

| 类型 | 处理 |
|---|---|
| 过期文档 | 块带 `valid_until`，过期块降权或排除；旧版本与新版并存时必须排除旧版 |
| 冲突文档 | 同一问题多版本答案 → 按文档优先级（版本、来源权威性）排序，并在引用里显示版本 |
| 含 PII 的块 | 入库前脱敏（见 agent-safety-standards 03），不脱敏不入库 |
| 表格错行 | 入库时校验列数，异常块标记并报警，不静默入库 |
| 重复内容 | content_hash 去重，多来源时保留权威来源 |

## 五、离线召回评测（改检索前必做）

| 指标 | 定义 | 门槛参考 |
|---|---|---|
| Recall@k | 期望块出现在前 k 条的比例 | k=10 时 ≥ 0.85 |
| MRR | 期望块排名的倒数和均值 | ≥ 0.6 |
| 无命中率 | 低于阈值被判无命中的比例 | 与真实"查不到"比例对齐 |
| 引用准确率 | 引用 id 属于召回集合且确实支撑结论 | ≥ 0.95（id 合法率应为 100%） |
| 上下文命中占比 | 进上下文的块中真正被用到的比例 | 过低说明 top_n 太大 |

要求：

- 固定 query 集（≥ 50 条，含 10 条以上"应该查不到"的）
- 每次改切分 / embedding / 阈值 / 重排，都要跑一遍并记录对比
- 评测集与线上 query 分布要对齐，冷门问法要覆盖
- 线上 badcase 定期回流成 query 集条目（回流机制归 agent-eval-standards）

## 六、自查

- [ ] 引用带 chunk_id + section_path，渲染前校验 id 属于召回集合
- [ ] 事实性段落缺引用时有处理策略（重答 / 标注）
- [ ] 无命中、部分覆盖、无权限三种结果分开处理，话术不泄露资源存在性
- [ ] 权限在检索层过滤，不是召回后靠提示词
- [ ] 过期 / 冲突 / PII / 错行 / 重复五类脏数据都有处理
- [ ] 离线评测指标齐全，改动检索前后有对比记录
