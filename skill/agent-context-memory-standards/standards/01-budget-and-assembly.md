# 01 上下文预算与组装

## 一、预算表（五段，必须给数字）

以 128K 窗口为例，起手比例：

| 段 | 占比 | 128K 时 | 说明 |
|---|---|---|---|
| 系统提示词（含不可变段） | 5%~8% | 6K~10K | 身份、硬约束、禁止项、输出格式 |
| 工具描述 | 10%~15% | 13K~19K | 工具多时先做检索式裁剪，再谈预算 |
| 历史（多轮） | 25%~35% | 32K~45K | 含摘要与关键事件 |
| 检索 / 外部内容 | 25%~35% | 32K~45K | 单条上限 + 总条数上限 |
| 输出预留 | 15%~20% | 19K~26K | 至少 1.5×最大输出长度 |

调整规则：

- 单轮任务（无多轮）：历史压到 5% 以下，把额度给检索
- 长对话客服：历史升到 40%，检索降，靠记忆补
- 工具密集型：工具描述先做分组或检索式选择，不允许靠挤占输出预留来解决

**加总必须 ≤ 窗口 × 0.95**，剩 5% 给 tokenizer 估算误差与系统注入。

## 二、配置形态

预算必须是配置，不是散落的魔数：

```yaml
context_budget:
  window_tokens: 128000
  system: 8000
  tools: 16000
  history: 40000
  retrieval: 40000
  output_reserve: 24000   # ≥ 1.5 × max_output_tokens
  compress_at: 0.75       # 达到 75% 触发压缩
```

代码里只允许读配置，禁止出现 `if tokens > 120000` 这类常量判断。

## 三、组装顺序（固定，不得重排）

```
1. 系统提示词不可变段（身份 / 硬约束 / 禁止项 / 输出格式）
2. 工具描述（按策略裁剪后的）
3. 长期记忆摘要（若有，≤ 预算的 5%）
4. 会话摘要（滚动摘要，替代被裁掉的早期历史）
5. 近期历史（原文，按时间正序）
6. 检索 / 外部内容（带来源标记，包在明确分隔符内）
7. 当前用户输入
8. 输出预留（空着，不填内容）
```

三条硬约束：

- **不可变段永不被裁剪**，也永不被摘要替换
- **外部内容必须包在分隔符里**并标注来源，与指令区分（细则归 agent-safety-standards）
- **顺序不得按"重要性"乱调**：把检索片段放在系统提示词前面是最常见的指令失效原因

## 四、多轮状态怎么保持

| 层 | 放什么 | 生命周期 |
|---|---|---|
| 会话状态（事实） | 已执行动作、已收集字段、已用工具、待确认项 | 整个会话，可序列化落库 |
| 会话摘要（投影） | 被裁掉历史的压缩版本 | 滚动更新 |
| 近期历史（原文） | 最近 N 轮原文 | 滑窗 |
| 长期记忆（沉淀） | 跨会话可复用的偏好 / 事实 | 按 TTL |

**会话状态不参与裁剪**，只允许归档；上下文只是它的投影。禁止把状态对象整个序列化后塞进提示词。

## 五、动态分配（同一会话内可调）

- 检索命中少（< 3 条）时，把剩余额度让给历史：`history_budget += max(0, retrieval_budget - used)`
- 历史被摘要压缩后，释放出的额度**不要自动填满**，留给输出预留更安全
- 每步都重新计算实际占用，并把各段实际 token 写进日志（字段见 agent-ops-standards）

## 六、自查

- [ ] 五段配额齐全且有具体数字，加总 ≤ 窗口 × 0.95
- [ ] 输出预留 ≥ 1.5 × 最大输出长度
- [ ] 预算来自配置，代码里无窗口魔数
- [ ] 组装顺序固定，不可变段在最前且不被裁剪
- [ ] 外部内容有分隔符与来源标记
- [ ] 会话状态与上下文分离，状态不整段进提示词
- [ ] 每步记录各段实际 token 占用
