# Agent 成本与可观测规范

## 定位

agent 的成本是**乘法**：步数 × 每步上下文 × 单价。没有计量就没有预算，没有 trace 就没有归因——出事时只能看到"这个月贵了 3 倍"，看不出是哪条链路、哪类任务、哪一步。

## 九条硬规则（可核对）

1. **每次模型调用必须记录用量**：prompt / completion / total tokens 与耗时，来自 API 返回而非本地估算
2. **每次工具调用必须记录耗时与结果码**：成功 / 失败 / 超时 / 被拦截分开计
3. **一条任务一条 trace**：一次模型调用或工具调用一个 span，父子关系明确
4. **结构化日志必填七字段**：session_id、trace_id、step_no、tool_name（模型调用记为 `llm`）、tokens、elapsed_ms、result_code
5. **单任务必须有成本上限**：token 或金额，达上限走"预算耗尽"分支，不允许静默继续
6. **成本要能按维度拆**：按任务类型、按模型、按工具，否则无法定位贵在哪
7. **缓存必须可判失效**：缓存键含租户与关键参数，命中率与命中成本收益要能看
8. **模型分级要有判据**：哪类任务用便宜模型，判据写进配置，不靠"感觉简单就用小的"
9. **告警阈值分三档**：提示（看趋势）/ 警告（当天处理）/ 严重（立即中断或降级）

## 三条反例（出现即返工）

- 埋点只记了"总 token"，出事时分不清是历史膨胀还是检索片段过多
- 成本上限写在提示词里让模型自己控制
- trace 只在入口打一个 span，模型调用与工具调用全挂在同一层，无法看出哪一步慢
