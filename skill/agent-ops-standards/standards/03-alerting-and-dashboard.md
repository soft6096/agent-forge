# 03 告警、降级与看板

## 一、告警三档

| 档 | 触发 | 响应 |
|---|---|---|
| 提示 | 趋势偏离（成本 +30%、P95 +20%） | 记录，周会看 |
| 警告 | 指标越线（错误率 > 5%、预算耗尽率 > 10%） | 当天处理 |
| 严重 | 不可用或成本失控（错误率 > 30%、单日成本超预算 2 倍、连续 5 分钟 0 成功） | 立即降级 / 中断 / 拉人 |

每条告警必须有：**指标定义、阈值、统计窗口、通知对象、处置动作**。只写阈值不写动作的告警等于噪音。

## 二、必配告警项（首批）

| 指标 | 建议阈值 | 说明 |
|---|---|---|
| 任务失败率 | 5% 警告 / 30% 严重 | 按任务类型拆开看，别只看全局 |
| 预算耗尽率 | 10% | 高了说明预算定得不合理或任务变复杂 |
| 平均步数 | 偏离基线 +50% | 常见于工具选错导致的反复重试 |
| P95 时延 | 偏离基线 +50% | 模型侧慢还是工具侧慢，靠 span 区分 |
| 单任务成本 P95 | 偏离基线 +50% | 成本长尾往往由少数任务贡献 |
| 工具错误率（按工具） | 20% | 单工具飙升通常是上游变更 |
| 拦截率（安全） | 突增 3 倍 | 可能是攻击，也可能是误拦 |
| 缓存命中率 | 跌破基线 -30% | 提示词或参数变化导致缓存失效 |

## 三、降级策略（按优先级执行）

```
1. 模型降级：切小模型（质量会降，需评测能发现）
2. 检索降级：减少召回条数、关闭重排
3. 工具降级：关闭非核心工具，只留主链路
4. 功能降级：只回答不执行（关闭写类与高危工具）
5. 熔断：拒绝新任务，返回明确话术 + 人工入口
```

四条约束：

- **降级必须可见**：日志与响应里标明"当前为降级模式"，否则用户以为功能坏了
- **降级必须可回滚**：开关化，恢复后自动或手动切回，有记录
- **降级不能悄悄改质量**：降级期间的结果**不得**进评测基线，否则基线被污染
- **安全相关过滤不参与降级**：任何情况下入向 / 出向过滤与高危确认不关闭

## 四、看板口径（四象限，缺一不可）

| 象限 | 指标 | 回答什么问题 |
|---|---|---|
| 效果 | 通过率、工具正确率（来自评测，本技能提供数据） | agent 干得对不对 |
| 成本 | 单任务成本、token 结构、缓存节省 | 贵不贵、贵在哪 |
| 效率 | 平均步数、P95 时延、工具耗时分布 | 慢在哪一步 |
| 稳定性 | 失败率、预算耗尽率、拦截率、降级时长 | 稳不稳 |

口径统一要求：

- 所有比率必须带**分母**（"通过率 82%"要写"82/100"）
- 时间窗口统一（今日 / 近 7 天 / 近 30 天），不许混用
- 成本与效果必须能按**同一维度**（任务类型）交叉看，否则无法回答"哪类任务性价比最差"
- 看板上的数必须能下钻到 trace，不能只是一个孤立的数字

## 五、自查

- [ ] 每条告警有指标定义、阈值、窗口、通知对象、处置动作
- [ ] 首批八项告警已配置，且能按任务类型 / 工具拆分
- [ ] 降级有优先级顺序、开关、可见标识、可回滚
- [ ] 降级期间结果不进评测基线；安全过滤不降级
- [ ] 看板四象限齐全，比率带分母，可下钻到 trace
