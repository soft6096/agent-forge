# 02 trace 与结构化日志

## 一、trace / span 结构

```
trace: task_id（一次任务一条）
├── span: step_1
│     ├── span: llm_call（模型调用）
│     └── span: tool_call（工具调用）
├── span: step_2
└── span: finalize（收尾：计费、审计）
```

规则：

- **一次任务一条 trace**，trace_id 在入口生成，全链路透传
- **一次模型调用 / 一次工具调用各一个 span**，父 span 是所属步
- span 必须有开始与结束（异常也要结束，标记 error）
- 跨进程（MCP、异步任务）通过 trace_id 透传，缺这一段就无法串起来

### span 必填字段

| 字段 | 说明 |
|---|---|
| trace_id / span_id / parent_span_id | 关系 |
| name | `llm_call` / `tool:query_order` / `step:N` |
| start_ms / elapsed_ms | 时延 |
| status | ok / error / timeout / blocked |
| attrs | 类型专属：模型 id、tokens、工具名、结果码 |

## 二、结构化日志必填七字段

每步固定打一条：

| 字段 | 示例 |
|---|---|
| session_id | `s_8f21` |
| trace_id | `t_9c02` |
| step_no | `3` |
| tool_name | `query_order`（模型调用写 `llm`） |
| tokens | `{"prompt":8200,"completion":210}` |
| elapsed_ms | `1240` |
| result_code | `ok` / `tool_error` / `blocked` / `budget_exceeded` |

这七个字段是 6.1 核对项 22~23 的判据依据：缺 session_id / trace_id 无法关联会话，缺 token 无法核账。

## 三、日志内容红线

- **不打印完整提示词与完整模型输出**到生产日志（需要时走采样 + 脱敏，单独存储）
- **不打印敏感字段明文**（证件、卡号、手机号、密钥），参数只存摘要哈希
- **不打印工具完整响应体**（可能含他人数据），只记结果码与关键 id
- 异常必须打 error 级别并带堆栈，但堆栈里若含请求参数需脱敏

## 四、日志级别约定

| 级别 | 用途 | 注意 |
|---|---|---|
| DEBUG | 提示词片段、中间变量 | 生产默认关 |
| INFO | 每步一条结构化日志、状态流转 | 主链路全靠它 |
| WARN | 重试、降级、裁剪触发、拦截 | 需要趋势观察 |
| ERROR | 任务失败、工具连续失败、预算耗尽 | 必须带堆栈与上下文 |

## 五、采样

- 全量采 INFO 会导致日志成本超过模型成本：**按 trace 采样**，一条任务要么全采要么不采，不要半条
- 采样策略：错误 100% 采、慢任务（P95 以上）100% 采、正常流量按比例（如 10%）
- 采样开关与比例进配置，出问题时能临时开到 100%
- 采样后的统计要除权，否则报表失真

## 六、关联与检索

必须能用以下任一键串起一次完整问题复盘：

- 用户 / 租户 → 会话 → 任务 trace → 步 → span
- 业务单号 → 工具调用记录 → trace
- 错误码 → 当天所有命中 → 按工具聚类

缺任何一个索引，复盘就会退化成"翻日志猜"。

## 七、自查

- [ ] 一任务一 trace，模型与工具调用各有 span，异常也结束 span
- [ ] 七字段齐全且在每步日志中
- [ ] trace_id 跨进程透传（MCP / 异步）
- [ ] 不打印完整提示词 / 敏感明文 / 完整响应体
- [ ] 采样按 trace 整条，错误与慢任务全采，比例可配
- [ ] 能从用户 / 业务单号 / 错误码三个入口反查 trace
