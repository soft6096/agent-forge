# 01 计量口径、成本核算与预算

## 一、计量口径（必须统一，否则报表对不上）

| 指标 | 口径 | 来源 |
|---|---|---|
| prompt_tokens | 本轮实际输入的 token | API 返回 |
| completion_tokens | 本轮输出 token | API 返回 |
| cached_tokens | 命中缓存的输入 token（有则单列） | API 返回 |
| tool_calls | 工具调用次数（成功 / 失败分开） | 调用方埋点 |
| steps | 主循环步数 | 骨架 |
| elapsed_ms | 单次调用耗时 | 调用方打点 |
| task_cost | 单任务金额 | 见第二节公式 |

三条禁令：

1. **禁止本地估算 token 代替 API 返回值**（分词器差异可达 20%，且估算不出缓存命中）
2. **禁止只记总量**：prompt 与 completion 必须分开，否则无法判断是上下文膨胀还是输出失控
3. **禁止把缓存命中算成全价**：缓存 token 单独计，否则成本虚高、优化判断失真

## 二、成本核算

```
task_cost = Σ_over_steps ( prompt_tokens × p_in + completion_tokens × p_out )
            + Σ_over_calls ( tool_cost )        # 付费工具才计
```

- 单价走配置表（按模型 id + 版本），不写死在代码里
- 报表保留两位小数，币种统一
- 按三个维度聚合，缺一个就无法定位：**任务类型 / 模型 / 工具**

## 三、预算上限（三层，缺一不可）

| 层 | 示例 | 超限行为 |
|---|---|---|
| 单步 | 单次调用输入 ≤ 窗口 × 0.95 | 走裁剪降级（context-memory 02） |
| 单任务 | token ≤ 200K 或金额 ≤ 0.5 元 | 终止，走"预算耗尽"分支，返回已完成部分 |
| 日 / 租户级 | 日成本 ≤ X，单租户 ≤ Y | 拒绝新任务或降级到小模型，并告警 |

硬要求：

- 上限是**配置项**，代码里只读配置
- 超限必须走**显式终止分支**，语义为"预算耗尽"，与"正常完成""步数耗尽"区分（见 agent-core-standards 五类终止）
- **不允许把预算控制交给提示词**让模型自己"注意节省"
- 上限值变更需记录（谁改的、为什么），因为它直接影响用户体验

## 四、缓存策略

| 类型 | 缓存什么 | 键设计 | 失效 |
|---|---|---|---|
| 提示词缓存 | 系统提示词 + 工具描述前缀 | 内容 hash + 模型 + 版本 | 提示词版本变更即失效 |
| 结果缓存 | 只读工具的相同参数结果 | 租户 + 工具 + 参数 hash | TTL（5~60 分钟）+ 显式失效 |
| 检索缓存 | 相同 query 的召回结果 | 租户 + query + 索引版本 | 索引更新即失效 |

四条约束：

- 缓存键**必须含租户**，否则跨租户串数据（安全红线）
- 写类工具结果**不缓存**（除幂等去重，那是另一套）
- 命中率与"命中带来的成本节省"都要能看，否则不知道缓存值不值
- 缓存的收益上限通常在主链路固定前缀部分；动态部分缓存收益低

## 五、模型分级路由

| 任务特征 | 建议档位 | 判据 |
|---|---|---|
| 意图识别、字段抽取、简单分类 | 小模型 | 输出结构化、答案空间小 |
| 多步工具编排、需要推理 | 中 / 大模型 | 需要规划与错误恢复 |
| 复杂规划、长文档综合 | 大模型 | 上下文长、判断多 |

要求：

- 路由判据写进配置（任务类型 → 档位），不是"if 感觉简单"
- 降级链明确：大模型不可用时可用哪个小模型顶上，降级后**质量指标必须能被评测发现**（否则降级悄悄发生）
- 记录每次调用用的模型 id，便于按模型拆成本与质量

## 六、自查

- [ ] prompt / completion / cached token 分开记录，来自 API 返回
- [ ] 工具调用次数与耗时已埋点，成功失败分开
- [ ] 单价走配置，成本可按任务类型 / 模型 / 工具三维拆
- [ ] 单步、单任务、日级三层预算上限存在且是配置
- [ ] 超限走"预算耗尽"显式分支，不静默继续
- [ ] 缓存键含租户，写类不缓存，命中率可观测
- [ ] 模型分级有配置判据与降级链，调用记录模型 id
