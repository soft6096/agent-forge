# Agent 工具规范

## 定位

工具是模型唯一的动作通道。工具定义写错时，模型选错工具、传错参数、重复写数据、把不可逆操作当查询执行——这些都不是"模型不聪明"，而是契约没写清楚。

## 九条硬规则（可核对）

1. **一个工具一件事**：名称用动词+名词，禁止 `doEverything`、`manageOrder` 这类聚合工具；一个工具内部若有两个以上不可分割的业务动作，说明该拆
2. **描述必须写"何时用 / 何时不用"**：这是模型选工具的唯一依据，只写"查询订单"等于把选择权交给运气
3. **参数必须给类型、必填性、约束、示例**：枚举型参数必须给完整取值，禁止"格式自定"
4. **副作用必须分级**：只读 / 写 / 高危三级，写与高危必须显式标注，不准留空
5. **写类工具必须有幂等键**：幂等键绑定会话或请求，去重窗口写明；靠"先查后写"不算幂等
6. **错误返回必须模型可读**：说明哪个参数错、允许什么值、下一步该怎么做，禁止只返回 HTTP 500 或堆栈
7. **权限与租户边界写在契约里**：所需角色、租户隔离方式、越权时的返回语义，不靠提示词约束
8. **超时与重试归属明确**：单次超时归工具，重试判定归调用方（骨架），工具内部不得自行无限重试
9. **工具数超过 15 个必须给选择策略**：分组 + 检索式选择，禁止把所有工具一次性塞进上下文

## 三条反例（出现即返工）

- 一个工具同时做"查订单 + 改地址 + 发通知"，模型无法只执行中间一步
- 写类工具只有 `INSERT` 前 `SELECT` 判重，没有唯一索引或幂等键，并发下重复写入
- 错误返回 `{"code": 500, "msg": "系统错误"}`，模型只能重试或放弃，没有任何自我修正空间

## 交付前

工具相关代码写完，过 `check-agent-standards` 的「工具」类核对项（第 5~8 项：描述与参数结构、副作用等级、幂等键、工具数量与选择策略），每项附文件行号证据；语义部分（描述是否写清何时不用、分级是否合理）按 `references/` 对应条目人工判定，禁止直接标 pass。
