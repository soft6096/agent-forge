# 操作外部系统的高危工具：契约细则

> 只在工具会改变 Agent 进程之外的状态时读这份：浏览器点击与表单提交、桌面 UI 操作、外部 API 写调用、发消息 / 邮件、云资源变更、文件与数据库写入。
> 本文只定**契约**，不教 Playwright / CDP 的 API，不做浏览器或沙箱产品选型，不写容器与部署配置——那些不在本技能边界内（见 SKILL-MAP 1.4）。

## 一、先判定是不是外部系统动作

命中任一条即按本节处理，不接受"只是查一下"的豁免：

- 执行结果在进程外可见（对方系统产生记录、页面状态变化、消息发出）
- 执行结果无法靠进程内回滚撤销
- 目标地址 / 选择器 / 命令 / 收件人由模型输出给出

判定口诀：**关掉进程后这件事是否仍然发生**。是，即为外部系统动作，副作用等级一律标 `dangerous`。

## 二、契约必填字段（缺一即返工）

| 字段 | 要求 | 为什么 |
|---|---|---|
| `side_effect` | 固定 `dangerous` | 不允许因"这次只点一下"降级成只读 |
| `target_allowlist` | 域名 / 路径 / 账号 / 资源 id 的枚举或前缀白名单 | 模型给的自由 URL 与选择器不得直接执行 |
| `action` | 封闭枚举，禁止自由文本 | 枚举外的值在参数校验阶段就拒绝 |
| `params_digest` | 工具名 + 归一化参数的摘要 | 确认的是 A 不能执行成 B |
| `idempotency_key` | 绑定会话 / 请求 + 业务键，写明去重窗口 | 外部系统常无事务，超时重发会重复生效 |
| `timeout_ms` | 单次超时归工具，数值写明 | 重试判定归骨架，工具不得自行无限重试 |
| `audit` | `trace_id / session_id / step_no / tool_name / target / params_digest / decision` | 事后能回溯到哪一步、谁批准、对什么目标 |

## 三、参数指纹与确认绑定

- 确认令牌绑定 `tool_name + params_digest + session_id`，令牌由人持有，模型与主循环都拿不到
- 令牌有过期时间；过期、拒绝、超时都各有明确返回，不能静默当成"已批准"
- 确认后参数发生任何变化，令牌立即失效，必须重新确认
- 示例实现见 `examples/three-guarantee-agent/README.md` 第六节（30 分钟过期、令牌绑定工具名与参数指纹）

## 四、结果未知：不盲重试

外部系统超时或连接断开时，状态可能是「已执行 / 未执行 / 未知」三种。契约必须：

1. 返回 `unknown` 而不是 `failed`，并在错误里说清这三种可能
2. 禁止骨架自动重试；由幂等查询确认状态，或转人工
3. 错误返回用三段式：哪个参数 / 目标错、允许什么值、下一步该怎么做；禁止只回 HTTP 500 或堆栈

## 五、三条反例（出现即返工）

- 工具参数里有 `url: string`，注释写"模型按需填写"——等于把执行目标交给不可信输出
- 超时后 `for i in range(3): call()`——外部系统可能已执行三次
- 确认项只记工具名不记参数摘要——确认"改 A 的地址"后能执行成"删 B 的账号"
