# 03 MCP 接入与外部服务包装

## 一、MCP 工具与本地工具的区别（必须先认清）

| 维度 | 本地工具 | MCP 工具 |
|---|---|---|
| schema 归属 | 自己定义，可改 | 服务端定义，只能适配 |
| 副作用透明度 | 自己标注 | 服务端未必标注，**必须自行补标** |
| 超时与重试 | 自己控制 | 受传输层与服务端共同影响，重试可能重复执行 |
| 鉴权 | 进程内 | 走 MCP 配置，凭据不进代码与日志 |
| 可用性 | 随进程 | 独立进程 / 远程，可能连不上 |
| 版本 | 跟代码 | 服务端升级可能悄悄改 schema |

由此得出三条硬约束：

1. **MCP 工具必须补副作用等级**：服务端不标注时，按"不确定即高危"处理，直至人工确认
2. **MCP 写工具必须有幂等键**：网络重试与客户端重连都可能重复投递，不能假设服务端去重
3. **接入前必须固定 schema 快照**：把服务端返回的工具定义存成版本化文件，升级时对比 diff，防止悄悄变化

## 二、MCP 接入检查清单

- [ ] 只连接可信来源，配置里写明服务名与用途
- [ ] 凭据走环境变量或密钥管理，**不进代码、不进日志、不进提示词**
- [ ] 连接超时与调用超时分别设置（连接 3~5s，调用按接口定）
- [ ] 服务不可用时有明确降级：报错给模型可读信息 / 跳过该工具继续 / 中断任务
- [ ] 工具定义落快照（`mcp/<service>/schema.snapshot.json`），升级前 diff
- [ ] 工具数量受控：不把整个服务端工具集全量注入上下文
- [ ] 有连通性自检（启动时 ping 或首次调用失败即告警）

## 三、外部 API 包装原则

包装不是转发，是**为模型重塑接口**：

1. **裁字段**：只暴露模型需要的字段，禁止把后端返回的 60 个字段直接给模型（也省 token）
2. **扁平化**：嵌套三层的响应压成两层，模型对深嵌套的字段引用准确率明显下降
3. **翻译错误**：后端 401/403/409/422 一律映射成 `permission_denied` / `conflict` / `invalid_argument`，并给出修正提示
4. **收敛参数**：后端要 12 个参数，包装成 3~5 个，其余用默认值或从会话取
5. **不跨语义**：一个 REST 端点不代表一个工具，按模型需要的行为切

## 四、工具描述与示例怎么写

description 固定三段：**做什么 / 何时用 / 何时不用**。

```
查询订单的当前状态与最近一次物流节点。
何时用：用户提供订单号，问"到哪了""什么时候到""是不是卡住了"。
何时不用：用户要取消或修改订单（用 update_order_*），用户只问退款进度（用 query_refund）。
返回：status、last_event、eta；订单不存在时返回 not_found。
```

参数示例优先于文字说明：

```json
{"order_no": "SO202611060001", "include_logistics": true}
```

- 每个工具**至少一个正例**；高危工具再加一个"不该这样传"的反例
- 示例里的值用真实格式，不用 `"string"` `"xxx"` 占位
- 参数描述里写单位与格式（金额分/元、日期格式），不要靠命名暗示

## 五、工具选择策略的实现

工具数超过 15 个时，三选一并在 3.1 架构方案里写明：

| 策略 | 实现要点 | 代价 |
|---|---|---|
| 分组 | 按业务域或阶段定义工具集，切阶段时重挂 | 需要在状态机里维护工具集切换 |
| 检索式 | 工具描述建索引，每轮按用户意图检索 top 5~8 注入 | 多一次检索调用，可能漏工具 |
| 分层入口 | 先 `list_capabilities`，再按返回结果挂具体工具 | 多一轮交互 |

三种策略都必须满足：**当轮注入工具数 ≤ 20**，且被裁掉的工具在提示词里明确告知"当前不可用"，避免模型编造调用。

## 六、自查

- [ ] MCP 工具已补副作用等级，写类有幂等键
- [ ] schema 已快照并纳入版本管理
- [ ] 凭据不在代码 / 日志 / 提示词中
- [ ] 连接与调用超时分别设置，有降级路径
- [ ] description 三段齐全，至少一个正例
- [ ] 工具数 > 15 时有策略，且当轮注入 ≤ 20
