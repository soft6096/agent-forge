# 01 工具粒度、命名与 schema

## 一、粒度怎么切

判据是**模型是否需要单独执行其中一步**，不是代码复用。

| 情况 | 结论 |
|---|---|
| 两个动作总是一起发生、中间不需要模型决策 | 合成一个工具 |
| 两个动作之间模型可能只看结果就停 | 拆成两个工具 |
| 一个工具内部有 if 分支决定走哪条业务路径 | 拆开，让模型显式选择 |
| 参数超过 8 个且过半是可选的 | 先怀疑粒度太粗 |
| 同一资源的查询 / 创建 / 修改 / 删除 | 分为四个工具，禁止 `manageX` |

反例与改法：

```
反例：manage_order(action="query|update|notify", params...)
改法：query_order / update_order_address / notify_order_customer
```

## 二、命名

- 动词 + 名词，蛇形或驼峰按语言惯例，**同一项目内必须统一**
- 动词取语义最窄的那个：`get_order_status` 优于 `get_order`
- 禁止：`do_`、`handle_`、`process_`、`xxx_utils`、`call_api`
- 名称里不要带版本号（`query_order_v2`）——版本靠契约变更管理

## 三、schema 必填九字段

每个工具一张卡，缺一即视为未定义完成：

| 字段 | 要求 | 常见错误 |
|---|---|---|
| name | 动词+名词，全局唯一 | 带空格、带大写混排 |
| description | 何时用 / 何时不用 / 返回什么 | 只写功能名 |
| parameters | 类型、必填性、约束、示例 | 全部 string、无 enum |
| side_effect | 只读 / 写 / 高危 | 留空或写"无" |
| idempotency | 写类工具必填：键名 + 去重窗口 | 写"天然幂等" |
| permission | 角色、租户隔离方式 | 写"已鉴权" |
| errors | 错误码、可读消息、模型可采取的动作 | 只给一个 500 |
| timeout | 单次超时 + 是否可重试 | 只在 HTTP 客户端设 |
| source | 本地实现 / MCP / 内部服务 | 留空 |

## 四、参数校验与拒绝语义

- **进入业务前先校验**：类型、范围、枚举、必填、跨字段依赖（如 `end_date >= start_date`）
- 校验失败返回**可修正**的错误：哪个参数、期望什么、当前值是什么

```json
{"ok": false, "error": "invalid_argument", "field": "status",
 "message": "status 只接受 PAID / SHIPPED / CLOSED，收到 'shipped'",
 "hint": "大小写敏感，请使用 SHIPPED"}
```

- 拒绝语义分三档，不得混用：
  - `invalid_argument`：参数问题，模型可自我修正
  - `permission_denied`：权限问题，模型不可重试，应转人工或告知
  - `conflict` / `rate_limited`：暂时性，可退避重试（重试次数由骨架控制）

## 五、工具数量与选择策略

- 上限参考：**15 个**。超过就要给策略，不是"小心点用"
- 三种策略，按场景选一：
  1. **分组**：按业务域分工具集，按阶段加载（如"订单阶段"只挂订单工具）
  2. **检索式选择**：用工具描述做向量检索，每轮只注入 top-k（一般 5~8）
  3. **分层入口**：一个 `list_capabilities` + 按需展开，代价是多一次调用
- 无论哪种，**同一轮上下文里的工具数不超过 20**；超出会显著拉低选择准确率

## 六、自查

- [ ] 每个工具只做一件事，内部无业务分支
- [ ] 名称动词+名词，无 manage / do / process
- [ ] 九字段齐全，无"天然幂等""已鉴权"这类空话
- [ ] 枚举参数给了完整取值
- [ ] 校验失败的错误返回带 field 与 hint
- [ ] 工具数 > 15 时有明确选择策略，且当轮注入数 ≤ 20
