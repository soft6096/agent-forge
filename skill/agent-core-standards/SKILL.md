# Agent 骨架规范

## 定位

约束 agent 的**运行时骨架**：循环怎么转、状态怎么存、什么时候停、失败怎么办。这一层写错的代价最高——骨架不对，工具和提示词怎么调都不稳。

## 十条硬规则（可核对）

1. **必须有最大步数**，且是可配置常量，不得写死魔数、不得依赖模型自己停
2. **终止条件必须穷尽**：正常完成、步数耗尽、预算耗尽、用户中断、安全拦截，缺一即不完整
3. **每步只做一件事**：调模型 → 解析 → 执行工具 → 回填结果，不允许一步里混多件事导致状态不可追溯
4. **三处超时齐全**：单次模型调用、单次工具调用、单任务总时长
5. **失败必须分类**：模型层 / 工具层 / 业务层 / 系统层，不同类走不同处置，禁止一个 catch 包住全部
6. **重试必须判定可重试性**：网络抖动可重试，参数错误与权限错误不可重试，禁止无差别重试
7. **写类操作必须幂等**：幂等键与会话/请求绑定，去重窗口明确
8. **模型输出一律视为不可信**：解析失败要能兜底，不得让解析异常冒泡成系统错误
9. **状态必须可序列化**：会话中断后能凭状态快照恢复，不允许只存在内存对象里
10. **循环内不得出现无上限的集合增长**：历史、工具结果、日志缓冲都要有上限

## 三条反例（出现即返工）

- `while (true) { ... }` 无步数与终止条件，靠模型输出 `done` 退出
- 工具异常统一 `catch (Exception e) { log.error(e); }` 后继续，导致无限重试同一失败工具
- 会话状态存在静态变量或单例字段里，多用户并发互相污染
