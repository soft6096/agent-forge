# 02 失败、超时、重试、幂等

## 一、失败分类（必须区分，禁止一个 catch 包全部）

| 类别 | 典型错误 | 处置 | 可重试 |
|---|---|---|---|
| 模型层 | 限流（429）、超时、内容过滤、返回格式坏 | 退避重试 / 换模型 / 降级 | 限流与超时可，内容过滤不可 |
| 工具层 | 网络超时、5xx、依赖不可用 | 退避重试 / 熔断 / 告知模型换路径 | 超时与 5xx 可（限次数） |
| 业务层 | 参数非法、校验失败、权限不足、资源不存在 | **不重试**，把可读错误回填给模型由它修正 | 不可 |
| 系统层 | 配置缺失、代码异常、数据库连接池耗尽 | 立即失败 + 告警 | 不可 |

硬要求：

1. 四类失败分别定义异常类型或错误码段，日志中可区分
2. 业务层失败必须转换成**模型可读**的错误消息（含哪个参数错了、允许值是什么），这是 agent 自我修正的前提
3. 系统层失败不允许被 agent 静默吞掉后继续循环

## 二、三处超时

| 位置 | 建议默认值 | 可配置 | 超时后行为 |
|---|---|---|---|
| 单次模型调用 | 30s（流式按首 token 10s + 空闲 30s） | 是 | 重试或降级模型 |
| 单次工具调用 | 10s（写类 30s） | 是 | 返回超时错误给模型 |
| 单任务总时长 | 120s（按业务定） | 是 | 强制终止 + 返回已完成部分 |

反例：只在 HTTP 客户端设了超时，主循环没有总时长上限，导致单任务挂 10 分钟消耗预算。

## 三、重试策略

| 项 | 要求 |
|---|---|
| 可重试判定 | 必须先分类再决定，禁止无差别 retry |
| 退避 | 指数退避 + 抖动，起步 500ms，上限 8~10s |
| 次数 | 单点最多 2~3 次，总重试次数有全局上限 |
| 熔断 | 同一工具连续失败 3 次，本次任务内熔断，不再尝试 |
| 幂等前提 | 写类操作重试前必须确认幂等键有效 |
| 记录 | 每次重试都要写日志：第几次、原因、耗时 |

禁止：

- 对业务层错误重试（参数错了重试一万次还是错）
- 重试期间不更新步序号，导致步数与实际调用次数不一致
- 无限重试直到成功（必须有全局上限）

## 四、幂等

写类工具（下单、发消息、扣款、建工单）必须实现：

| 要素 | 要求 |
|---|---|
| 幂等键 | 由 会话 id + 步序号 + 工具名 生成，或由业务主键派生 |
| 去重存储 | 至少覆盖去重窗口（建议 24h），记录首次执行结果 |
| 重复请求返回 | 返回首次执行结果，不重复执行，标记 `deduplicated: true` |
| 键的作用域 | 与会话绑定，跨会话不共享（避免不同用户撞键） |

反例：工具内部用 `SELECT` 后 `INSERT` 判重但无唯一索引，并发下双写。

## 五、死循环识别

三种可观测信号，任一命中即应终止并归因：

| 信号 | 判定方式 | 处置 |
|---|---|---|
| 重复调用 | 同工具 + 参数指纹连续出现 ≥ 3 次 | 终止，回填"该调用无进展"给用户 |
| 无进展 | 连续 3 步无新增信息（无新工具、无新结果） | 终止，返回当前结论 |
| 用量异常 | 单步 token 超过预算的 50% 或累计逼近上限 | 压缩上下文或终止 |

实现要求：

- 参数指纹 = 工具名 + 参数规范化后的哈希，需排除时间戳、随机数等易变字段
- 命中后在日志中写明第几步、哪个工具、参数摘要
- 禁止仅靠模型自我判断"我卡住了"

## 六、自查

- [ ] 四类失败有独立错误码或异常类型
- [ ] 业务错误已转成模型可读消息
- [ ] 三处超时齐全且可配置
- [ ] 重试有退避、上限、熔断
- [ ] 写类工具有幂等键与去重存储
- [ ] 有至少一种死循环识别信号
