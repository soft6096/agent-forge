# 03 会话、并发、中断恢复

## 一、会话状态必须持久化的字段

| 字段 | 说明 | 缺了会怎样 |
|---|---|---|
| session_id | 全局唯一 | 无法关联日志与计费 |
| trace_id | 一次任务一个 | 无法串联模型与工具调用 |
| 步序号 | 当前第几步 | 断点恢复错位、幂等键重复 |
| 阶段状态 | 状态机当前状态 | 恢复后不知从哪继续 |
| 已调用工具清单 | 工具名 + 参数指纹 + 结果摘要 | 无法判死循环 |
| 累计 token / 成本 | 分区统计 | 无法执行预算终止 |
| 待确认项 | 高危操作待人工确认的内容 | 恢复后丢失授权上下文 |
| 用户输入历史 | 原文或摘要 | 无法重放 |

规则：状态必须能序列化成 JSON 完整落盘，不允许只存在内存对象或被拆散在多个静态字段里。

## 二、并发模型

| 场景 | 做法 |
|---|---|
| 同一会话并发请求 | 串行队列，后来的排队或拒绝，禁止并行改同一状态 |
| 不同会话 | 完全隔离，状态按 session_id 分区，禁止共享可变对象 |
| 多租户 | 租户 id 进状态与日志，检索与工具调用必须带租户过滤 |
| 长任务 | 异步化 + 状态查询接口，不占着连接等 |

反例（高频）：

```
// 反例：单例里存当前会话，两个用户同时用就串
@Service
public class AgentService {
    private ConversationState current;
}
```

## 三、中断与恢复

| 要求 | 说明 |
|---|---|
| 可中断点 | 只在步边界中断，不允许在工具执行中硬中断 |
| 快照时机 | 每步结束后落一次快照 |
| 恢复语义 | 从最后一步的**下一步**继续，不重跑已完成工具 |
| 恢复校验 | 恢复时校验幂等键与已执行工具，防止重复副作用 |
| 超期 | 快照设过期时间（建议 24h），过期后只能新开会话 |

## 四、会话与上下文分离

会话状态是**事实**（做过什么、花了多少），上下文是**投影**（这一轮给模型看什么）。

- 上下文由 `agent-context-memory-standards` 负责裁剪（预算声明、裁剪压缩、输出预留）
- 会话状态不允许被裁剪，只允许归档
- 禁止把会话状态直接整段塞进提示词

## 五、日志与可观测（骨架侧必做）

每步固定打一条结构化日志，字段：

```
session_id, trace_id, step, phase, action(model|tool), name,
tokens_in, tokens_out, cost, duration_ms, result_code
```

规则：

- 一条日志一行，禁止多行拼接
- 禁止打印完整提示词与完整工具结果（脱敏、截断，默认 200 字）
- 异常日志必须带堆栈，且带 step 与 action 上下文
