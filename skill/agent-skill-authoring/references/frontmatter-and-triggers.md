# frontmatter、触发词与触发测试

> 本文件是 `SKILL.md` 硬规则 1 / 2 / 3 / 8 的判据细则。
> 全部结论来自本仓 `evals/README.md` 的 v1~v5 真实选择器实测，不是凭空立法。改动前先读该记录的判定表。

## 1. frontmatter 只写两个字段

| 判据 | 通过条件 | 机械核对 |
|---|---|---|
| 字段集合 | 只有 `name` 与 `description` | `head -5 skill/*/SKILL.md` |
| name 一致 | 与所在目录名逐字相同 | 目录名与 frontmatter 对比 |
| description 职责 | 只回答「何时用」，不写教程、不复制正文 | manual |
| 长度 | ≤ 1024 字符，超了客户端直接不加载 | `check-agent-standards/scripts/check_agent_standards.py` 的 `len(desc) > 1024` 判定 |

`name` 一律小写连字符；agent 领域技能统一 `agent-` 前缀，核对与元技能不带前缀。前缀不是装饰，是为了避免与通用方法论技能抢叫法（SKILL-MAP 1.3）。

## 2. description 的四段式

```
<一句话职责与不做什么>。触发：<用户原话>。<强制加载条件>。边界：<归哪个技能>；<不归我>。
```

- **触发语取真实原话，不取术语**。用户不会说「会话状态持久化异常」，会说「会话中断之后恢复不了状态，只能从头再问一遍」。
- **强制加载条件**写死范围，例如「任何新增或修改技能目录、SKILL.md、description、references 前必须加载本 skill」（含只改一句触发词的零散改动）。
- **边界必须点名归属技能**，写成「技能装了但不生效、版本不对、软链失效归 agent-forge-source-law」，而不是含糊的「不归我」。点名才能让选择器在相邻技能之间做出唯一判断。

## 3. 触发语与否定边界必须成对改

只给 A 补触发词、不给相邻技能 B 补否定边界，B 就会抢走原本 pass 的样本。这是 v1 的 T18 与 v3 的 T05/T18 共同暴露的失败模式。

改一个 description 时，同步检查：

1. 新触发词里有没有与别的技能重叠的词（「会话」「感觉效果」「技能不触发」都是实测踩过的坑）
2. 所有被重叠的技能，边界里是否点名写清归属
3. `skill-trigger.jsonl` 里对应样本的 `must_not` 是否需要补技能名
4. 基准文档（SKILL-MAP 职责卡）里的「触发说法 / 边界」是否同步

## 4. 触发测试口径

样本分层：`smoke`（主路径）、`regression`（历史易错）、`adversarial`（负样本与边界）。每条含 `expect_main`（必须命中）、`expect_optional`（可伴随）、`must_not`（命中即 fail）、`judge`、`source`。

判定表（与 `evals/README.md` 一致）：

| 条件 | 结论 |
|---|---|
| `expect_main` 有技能未命中 | fail，漏触发 |
| `must_not` 有技能被命中 | fail，误触发，比漏触发更危险 |
| 其余，含 `expect_optional` 命中 | pass |

四条执行纪律：

1. **逐条独立发送**：一条消息放多条原话，选择器只对这条复合输入做一次判定，产生的 `use_skill` 不能拆开冒充多条结果。
2. **各开干净会话**：同一会话内连续逐条发会有上下文累积；v3 里 T18 的推理出现「按前几轮模式」「第五条」，就是污染证据。
3. **新会话才扫得到新技能**：技能目录在会话启动时扫描，旧会话看不到改动。
4. **盲判不能冒充实测**：让不知道答案的子代理只读各 SKILL.md 的前 12 行（frontmatter）判断会加载哪些技能，可用于快速回归；禁止它读 `evals/`、`README.md`、`SKILL-MAP.md`。真实结论一律以会话里的 `use_skill` 工具调用为准，模型自述不算。

## 5. 改 description 的固定流程

1. 先改基准文档的职责卡与边界，再改代码
2. 同时改本技能触发语与相邻技能的否定边界
3. 补/改 `skill-trigger.jsonl` 样本，真实跑出来的缺陷标 `source=真实` 并写证据备注
4. 跑 smoke + adversarial 两层盲判回归
5. 推送后重跑安装，让新 description 进入安装副本
6. 在**新开的、各自独立的干净会话**里逐条实测，读 `use_skill` 提取真实加载
7. 回填 `evals/README.md` 判定记录；旧轮次结论标注「对旧 description 成立」，不要删数字

## 6. 三条实证教训

| 现象 | 结论 |
|---|---|
| 五句原话合并成一条消息 | 整轮作废，不得回填判定表 |
| 同会话逐条发，后几条继承前文技能上下文 | 该轮结果只能标「有限定」，不能算独立实测 |
| 盲判全 pass 但真机漏触发（v3 的 T05/T18） | 盲判结论不是验收结论，必须真机复测 |

## 7. 可核对项

- [ ] frontmatter 只有 `name` / `description`，`name` 与目录名一致
- [ ] description 含触发语、强制加载条件、点名归属的否定边界
- [ ] description ≤ 1024 字符
- [ ] 新增/修改触发词时，相邻技能的边界与样本 `must_not` 同步
- [ ] 样本逐条独立发送、各开干净会话
- [ ] 判定记录写明是盲判还是真实选择器实测
