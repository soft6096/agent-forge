## 一、循环形态

| 项 | 内容 |
|---|---|
| 选定形态 | 工具循环：模型决定是否调用工具，工具结果回填后再进模型，直至给出最终答复或触发终止 |
| 选择理由 | 任务边界窄（判定是否在保 + 给条款依据），单轮决策即可完成；引入规划层只会增加步数与不确定性 |
| 放弃的备选与原因 | 规划-执行：步骤固定，规划层是额外 token 开销；多 agent：无跨域协作需求，反而引入一致性问题 |
| 最大步数 | 8（config/agent.toml:18 max_steps） |
| 终止条件 | 正常完成 / 步数耗尽 / 预算耗尽 / 用户中断 / 高危拦截（五类见 src/tga/loop.py:35） |

单任务总时长上限 120s（config/agent.toml:56 task_ms），超时按 step_exhausted 终止并附说明（src/tga/loop.py:138）。

## 二、状态机

| 阶段 | 进入条件 | 动作 | 退出条件 | 失败去向 |
|---|---|---|---|---|
| 检查点 | 每步开始 | 检查取消信号、预算、任务总时长 | 全部通过 | 分别终止为 cancelled / budget_exceeded / step_exhausted |
| 上下文投影 | 调用模型前 | 按预算表投影，超限走三级降级 | 投影成功 | 第三级仍超限 → blocked 并告知不足（src/tga/context/window.py:116） |
| 模型调用 | 投影完成 | 一次模型调用，记录 token 与耗时 | 返回文本或工具调用 | 可重试错误按退避重试；不可重试 → blocked（src/tga/loop.py:167） |
| 工具执行 | 模型给出工具调用 | 校验参数 → 幂等检查 → 副作用判定 → 执行 | 返回结构化结果 | 参数/权限类错误回填模型自我修正；高危未确认 → approval_required |
| 收敛校验 | 工具执行后 | 用「工具名 + 参数」签名比对最近三步 | 签名不重复 | 连续 3 步相同 → blocked（src/tga/loop.py:269） |
| 输出过滤 | 模型给出最终答复 | 出向脱敏 | 过滤完成 | 过滤异常按 blocked 处理 |
| 终止 | 任一终止条件 | 落快照、写日志、返回 TaskResult | — | — |

## 三、上下文预算表

| 区段 | 预算（tokens） | 占比 | 溢出时处理 |
|---|---|---|---|
| 系统提示词 | 8000 | 8.3% | 不可裁，超限即报错 |
| 工具描述 | 16000 | 16.7% | 按分组与相关度裁剪 |
| 历史对话 | 8000 | 8.3% | 滚动摘要 + 保留最近 12 条原文 |
| 检索片段 | 40000 | 41.7% | 折叠外部内容（截断 + 摘要） |
| 输出预留 | 24000 | 25.0% | 不可裁，低于 1.5 × max_output_tokens 即判不足 |
| **合计** | **96000** | **100%** | 占窗口 75.0%，校验线为窗口 × 95% = 121600 |

裁剪触发阈值 75%（config/agent.toml:41 compress_at），不靠报错兜底；裁剪只发生在投影副本上，会话状态保持完整，这是中断恢复不丢东西的前提（src/tga/context/window.py:1-6）。

## 六、降级路径

| 故障 | 降级行为 | 用户可见提示 |
|---|---|---|
| 模型不可用 / 超时 | 可重试错误退避重试；超次数后 blocked | detail 写明「模型层不可重试错误」或超时步号 |
| 工具失败 | 结构化错误回填模型，模型可换参数重试；不可重试码直接告知 | 答复中说明缺失信息与下一步 |
| 检索无命中 | 不编造，明确说未查到并转人工 | 「未查到相关规定，建议转人工复核」 |
| 超预算 | 立即终止，不当成功返回 | detail 写明预算耗尽类型（token 或金额） |
| 触发安全拦截 | 高风险写操作转人工确认；注入内容打标后忽略指令 | approval_required + 待确认项说明 |
